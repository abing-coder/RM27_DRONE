# 仿真场景与道具

[返回系统介绍](../README.md)

地图采用 Gazebo SDF，默认且唯一入口是 `ws/src/rm_field_gazebo/worlds/rmuc2027_official.world`，规划地图为同包的 `config/field_map_official.yaml`。无人机本体使用 `ws/src/rm_drone_description/urdf/rm_drone.urdf.xacro`；地图不使用 URDF。

| 后缀 | 用途 |
|---|---|
| `.world` / `.sdf` | 场景、模型、位姿、碰撞与插件定义 |
| `.stl` / `.dae` | 三维几何；带地面纹理的网格使用含 UV 的 DAE |

## 新赛季 STEP 地图

用户提供的 `RMUC2027_V1.0.0.stp` 已转换为完整 Gazebo 场景；`能量单元.stp` 是直径约 95 mm、高约 150 mm 的独立能量单元，不是中央能量机关。完整场地中已经有两处补给站、合计十二个单元，不再重复叠放。独立模型 `rmuc2027_energy_unit` 可复用，质量与碰撞为简化值，尚未模拟抓取、磁吸或安装。

```bash
./sim.sh auto_start:=false
# 按默认配置启动自动任务
./sim.sh
```

默认启动新地图，无需指定 `field`；兼容显式传入 `field:=official`，旧地图选项已移除。新版保留 81 个 CAD 叶实例、40 组唯一几何及面颜色，两个基地、两个前哨站、能量机关、原生飞镖靶、机库与能量单元均来自 STEP。部分复用组件的红蓝面颜色按所属队伍修正。旧版世界文件和导航地图已删除；RViz、imshow、双目、彩色、深度与点云默认配置不变。

装甲保留范围：

| 部位 | 几何及识别范围 |
|---|---|
| 每方基地 | 保留 CAD 的六组装甲结构：三块上部标准小装甲，加三组闭合护甲后的本体装甲；不在护甲外侧伪造额外标准板 |
| 每方前哨站 | 保留三块标准小装甲及原生倾角，固定不转 |
| 标准装甲补充 | 共十二块，沿 CAD 原正面补贴纸、红蓝发光灯条和 1 mm 接触面，原有外壳保留；四角、PnP 尺寸、板面法向与接触面共用坐标 |
| 其他靶面 | CAD 自带的飞镖靶、能量机关及基地本体装甲几何保留；不作为现有四关键点模型的标准装甲导航目标 |

新版保持 CAD 静止姿态，尚未实现基地护甲开闭、飞镖靶移动或能量机关激活判定；旧版 `/sim/field/*` 道具运动控制未接入当前场地。新增十二块标准板配置实际接触插件，但完整冲击任务仍需在新几何上单独验收，不能将模型导入视为赛事得分验证。

坐标以米计，地图 +X 指向蓝方。原 CAD 为毫米、Z 向上，平移场地中心后绕 Z 旋转 180°；原始 STEP 不修改。机库 H 台面实测 1.6 m，生成的 `field_runtime_official.yaml` 同时提供出生点、导航和视觉覆盖参数，并校验世界/地图 SHA-256，避免换了外观却沿用旧目标坐标。当前仿真规划上限为 2.2 m、相对起飞高度 0.5 m、障碍膨胀 0.14 m；默认 EGO 模式增加 20 Hz 深度在线融合与局部重规划，见[导航文档](navigation.md)。这些高度、膨胀与采样率是适配参数，不是比赛规则数值。

静态物理碰撞使用保留拓扑、按颜色分组简化的 STL；规划使用 CAD 表面生成的 0.15 m 保守体素盒，不使用整块场景的包围盒。ToF 地形查询另用 CAD 向上三角形，保留坡面和分层高度，不用体素顶面冒充台面。规划体素保守覆盖会缩小窄通道；实机仍需实测地图与避障验证。

### 离线重新生成

已经包含生成资源，普通启动不读取 STEP，也不需要安装 CAD 库。需要重建时，在仓库根目录执行，缓存目录放在仓库外：

```bash
python3 -m venv /tmp/rm27-cad-env
/tmp/rm27-cad-env/bin/pip install -r ws/src/rm_field_gazebo/scripts/requirements-cad.txt
/tmp/rm27-cad-env/bin/python ws/src/rm_field_gazebo/scripts/gen_official_field.py \
  --field-step RMUC2027_V1.0.0.stp --energy-step 能量单元.stp \
  --cache-dir /tmp/rm27-cad-cache
```

第一次转换完整装配耗时较长；成功缓存按源文件哈希复用，不重复导入 STEP。修改布局后运行同一命令会同步重建世界、规划地图和启动清单；源 CAD 版本改变必须重新审查 `config/official_layout.yaml` 中的装甲安装面，不能直接套用旧锚点。生成后重新编译 `rm_field_gazebo`、`rm_drone_bringup`。原始文件哈希、转换精度与来源见 [SOURCE.md](../ws/src/rm_field_gazebo/models/rmuc2027_official/SOURCE.md)。

## 装甲与场地道具

装甲正面图案分别取自本地《机器人制作规范手册 V1.0.0（20261015）》印刷第 88–89 页（PDF 第 89–90 页）的附录图 1、3，版权归 DJI；提取为 `rm_armor_outpost.png`、`rm_armor_base.png`，不再使用占位数字。图案仅映射正面并保持原比例，灯条单独使用红蓝自发光材质。装甲安装位置与倾角来自新赛季 CAD，标准小装甲灯条间距为 125 mm，PnP 参数与生成几何一致。前哨站固定不转。

冲击导引区分装甲板面中心与机身中心，使用地图完整法向及预期末端近水平姿态，补偿简化桨保碰撞盒的接触点。`mission.yaml` 的 `body_radius=0.07`（节点默认）与 `body_half_height=0.0225` 对应当前 URDF 的 140×140×45 mm 盒；更改机身几何时应同步调整。补偿不追随加速时的瞬间俯仰，沿补偿后的板心高度接近，避免目标被不断抬高后先碰到基地上方的飞镖模块。

前哨站待机距离为3m，基地观察点相对补偿接触中心向外1.5m、向上0.8m。末段按`attack_acceleration`（2m/s²）加速到`attack_speed`（1.7m/s）；本轮须从1.2m外重新接近、实际接近速度超过1m/s，并收到匹配装甲的物理接触事件。撤离按剩余距离减速，避免位置阶跃造成猛倾斜掉高。再次接近前稳定位置与速度，`attack_height_tolerance`为8mm，`attack_vertical_speed_tolerance`为0.03m/s；这些是仿真调参，实机须按噪声与实际动力学重新验证。

任务中的 `attacks` 只统计当前无人机、本次接近、当前目标装甲的实际接触事件；IMU 加速度突变仅触发撤离，穿过板面也不会被当作接触。接触插件按 500 Hz（当前 2 ms 物理步长）采样，入射法向速度使用碰撞响应之前的物理步记录，避免把碰撞后减速误报为入射低速。任务接触次数仍不是裁判得分；力、时长、冲量及速度门限属于模拟裁判假设，不代表官方判定。

当前能量机关、飞镖靶、基地本体与护甲均使用 STEP 原生几何，机构保持静止。旧图的模型、转换历史与上游版权记录仍见[来源文档](credits.md)，不作为当前场地的运动接口说明。

## 桨保接触模型

机体碰撞保持原包络，桨保接触暂取刚度2000N/m、阻尼2*sqrt(m*k)，150g时约34.6N·s/m。
这组假设对应毫米级变形，避免刚性碰撞集中在单个2ms物理步；装甲接触、冲量和碰撞后定位仍须真实验收。
刚度/阻尼尚无实机标定数据，属于仿真模型参数，不是赛事规定，也不能证明实际桨保的碰撞性能。
碰撞体名称与`base_link`匹配，防止URDF转SDF时丢弃连杆的接触扩展。
验收脚本实际调用`gz sdf -p`，逐项比较转换前后的kp、kd与摩擦系数，缺失或不一致就停止测试。
转换行为可查阅[SDFormat的碰撞扩展匹配实现](https://github.com/gazebosim/sdformat/blob/sdf9/src/parser_urdf.cc)。
